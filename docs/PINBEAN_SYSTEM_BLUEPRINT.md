# PinBean 完备系统蓝图

## 当前判断

本蓝图是产品方向与实现盘点，不是发布验收报告。主交付是 uni-app 微信/H5；Web 的 AI、Focus、生成色板筛选和放大镜是 Web 专属交互及参考，不自动成为主客户端能力或 Core 契约。当前可靠性与项目协议收口正在实施，新增代码是否通过以本轮实际门禁记录为准，不能沿用历史 H5/真机结果签字。

PinBean 不应该只做“图片转像素格”。更完整的系统应覆盖四段连续工作：

1. 选题：找到适合拼豆传播和制作的图像主题
2. 制图：生成干净、可编辑、可导出的拼豆图纸
3. 制作：告诉用户尺寸、颗数、颜色、拼板、耗时和风险
4. 发布：把成品过程转成小红书/抖音内容，反过来验证选题

本轮未能直接拉取小红书图片：当前环境缺少 `xiaohongshu-mcp` 和 `xiaohongshu-login` 二进制，`status.sh` 也因脚本不可执行而无法完成登录态检查。后续如果要做真实内容调研，应先安装小红书 MCP、扫码登录，再跑 `search_feeds`，只记录选题和结构观察，不抓取他人图片做训练数据。

## 外部信号

公开资料显示，拼豆内容的传播重点不是“算法多高级”，而是低门槛、可展示、可送人、可持续换主题。新浪科技报道提到，拼豆靠小红书笔记、教程视频和社群分享形成 UGC 传播，同时要持续有新图纸、新主题、新应用场景。SmartHey 报道也提到小红书上存在“来图定制”服务，中等复杂度作品常要 7-8 小时。竞品 `pindou.top` 已把材料清单和 29×29 分板 PDF 导出列为核心功能。

2026-06-05 追加观察：公开搜索结果里，`pindou.chat` 已直接强调“小红书爆款文案”和一键导出分享；`perlerbeadsnew.zippland.com` 提供社区画廊和分享码导入；`bitbead.pomodiary.com` 把真实尺寸、29×29 板数、采购清单作为核心卖点。这进一步说明 PinBean 的重点应放在“作品用途预设、制作管理、可分享导出”，而不是单纯增加像素化参数。

因此 PinBean 的近期优先级应是：

- 把用户从“生成图纸”继续带到“买豆、分板、开拼、发布”
- 让图纸难度、耗时、备料和分板一眼可见
- 用发布文案和复盘字段服务小红书/抖音内容增长

## 产品闭环

### 1. 选题层

目标：让用户上传前就知道什么图适合做拼豆。

应沉淀的判断：

- 主体清晰、背景简单、轮廓强，比复杂照片更适合低格数图纸
- 可爱角色、挂件、小礼物、节日主题更适合内容传播
- 真实照片需要更高格数和更多颜色，适合作为进阶玩法

后续功能：

- 选题模板：头像、挂件、钥匙扣、节日礼物、人物照片
- 上传前提示：建议裁剪成主体居中、背景少的图
- 内容标签库：按主题自动给发布文案附带标签

### 2. 制图层

目标：稳定产出可制作图纸，而不是追求算法参数堆叠。

当前主链路：

- 上传图片
- 选择色板
- 选择尺寸
- 选择卡通/写实
- 生成网格
- 可选去背景、编辑、导出

优先补强：

- 已统一核心空格模型为 Numeric Grid 的 `0 = EMPTY`，非零格通过局部表映射 stable Color ID；`isExternal` / `key` 仅可作为 Web 兼容 View Model，不能成为核心目标模型
- 导出设置简化版：网格、色号、坐标、色卡统计
- 颜色简化建议：当颜色数过多时，引导用户用高亮和替换合并相近色

### 3. 制作层

目标：用户一眼知道“这张图能不能做、要准备什么”。

已落地：

- 生成后展示制作评估
- 上传后可选择作品用途预设：挂件、礼物、照片、大图，自动调整尺寸和处理风格
- 显示难度、图纸尺寸、颗数、用色、预计耗时、拼板数量
- 编辑或去背景后自动刷新评估
- 颜色清单显示建议备料数，按约 8% 损耗向上取整
- 一键复制备料清单，包含实际颗数和建议备料数
- 多板作品显示 29×29 标准板分板计划，并支持复制每块板的行列范围
- 根据主色数量和分板情况给出推荐制作顺序
- 支持按色号标记制作进度，显示完成色数、完成颗数和百分比
- 复制备料清单时带上当前制作进度和每个色号的完成状态
- 多板作品支持按分板标记完成状态，复制分板时带上每块板状态
- 当前已保存项目支持本地恢复图纸及匹配内容 Hash 的色号/分板完成状态；不是任意历史图案版本的永久恢复库
- 可复制制作进度/完成复盘文案，用于过程记录和小红书更新
- 维护最近制作作品索引，可复制当前作品摘要
- 多板作品支持按 29×29 标准板分别导出局部图纸，保留原始行列编号
- 分板导出支持只导出未完成分板，配合制作进度减少重复保存
- 分板计划显示每块板的主色统计，复制分板时附带每板颜色清单
- 最近制作记录可查看、复制摘要或删除，最多 8 条；它是摘要索引，不保存每件历史作品的完整网格，不能点击恢复任意作品
- 备料清单支持保存为图片，包含色板、实际颗数、建议备料、进度和每个色号状态
- 当前作品支持命名，名称会进入本地进度和最近制作记录
- 多板作品支持保存分板合集长图，用于总览分板和发布过程图

后续功能：

- 多作品完整恢复：保存并恢复每件历史作品的网格与状态；当前仅最后项目恢复和手动项目文件导入可恢复完整作品

### 4. 发布层

目标：让工具服务内容增长，而不是只停留在本地制作。

已落地：

- 一键复制发布文案，包含尺寸、颗数、颜色数、难度、耗时和建议
- 发布文案支持成品展示、制作教程、挑战记录三种模板
- 一键复制发布包，包含 20 字以内标题、首图建议、正文、标签和发布前检查清单
- 发布包会根据作品用途预设区分挂件、礼物、照片、大图的内容卖点
- 支持保存 3:4 发布封面图，把图纸缩略图、尺寸、颗数、用色、难度、耗时和主色消耗整合成小红书首图素材
- 发布复盘字段已经实现：主题、首次发布时间、点赞、收藏、评论、转化和备注；随当前项目恢复和项目文件保存，最近制作显示摘要。数据由用户手工录入，不是平台指标自动采集

后续功能：

- 过程图导出：原图、网格图、色卡图、成品照片组合成长图；待源图/成品素材可以随项目恢复后实现，避免只在当前会话可用
- 基于复盘记录的选题比较与建议；现有字段保存不等于已完成增长分析系统

## 开发顺序

1. 稳住 miniapp 当前生成闭环，不再追加复杂参数
2. 完成制作层：评估、备料、分板
3. 补齐导出层：设置弹窗、色卡布局、分板导出
4. 做发布层：文案模板、长图组合、内容复盘
5. 最后再做 AI 原图生成和 LoRA 数据闭环

## 边界

- 不用他人小红书图片训练模型
- 不把复杂算法选项暴露给普通用户
- 不为了“完备”增加无法验收的后台系统
- 每次新增功能都必须能进入“生成图纸 -> 制作 -> 发布”的实际链路
