# uni-app 微信入口切换审计

> 审计日期：2026-09-01
> 更新日期：2026-09-07（门禁与证据边界说明；未新增设备验收）
> 目标：确认 `apps/miniapp-uni/` 作为根微信开发者工具入口后的交付状态。
> 原则：旧原生版完整保留在 `v1` 分支，只作历史参考；H5、构建和模拟器验证不能替代真实相册、分享、触摸和设备性能验收。

## 结论

根微信入口已经切换到 `apps/miniapp-uni/dist/build/mp-weixin/`。uni-app 覆盖 PinBean 主交付闭环：选择图片、确定性生成、编辑、去背景、制作管理、原版导出设计、项目恢复和发布复盘。切换前发现的阻塞项已经补齐：五套供应商色号贯穿生成/项目/导出，编辑器可从完整 291 色供应商色板加入新颜色，并补齐连续画笔、吸管、分板主色摘要和相册拒绝后的设置恢复。

切换完成不代表所有平台人工验收完成。相册写入、微信文件分享、触摸坐标、设备内存、80×80 导出耗时和 iOS/Android 差异仍须作为真机 gate 单独记录。

## 主链路审计

下表“已覆盖”保留历史实现与当时验证范围，不代表本轮可靠性、v2 项目交换和进度收口已重新验收。新增实现须另附当前工作树/提交、命令和输出证据；本文未运行新 H5 smoke、微信模拟器或真机。

## 分层门禁

- `npm test`：Core、palette、Web 与 uni 单测。根调用 uni test 复用前序共享包构建；独立运行用 `npm run test:uni`。
- `npm run check`：全仓类型、lint、fixtures、测试及各平台构建。
- `npm run test:h5:full`：先构建 H5，runner 在空闲 loopback 端口提供页面，或使用 `PINBEAN_H5_URL`。临时双色夹具分别运行两种生成模式和八个完整分支，产物与命令详见 README。新增 runner/CI 当前仅静态检查，尚待实际执行。
- `npm run test:wechat:smoke`：微信业务链 mock 验证，Canvas 写入、临时 PNG、相册保存和文件分享存在替身；不证明真实成图、权限或分享成功。`reLaunch` 只代表路由重启，不能代替完全退出微信后冷进程恢复。
- `.github/workflows/check.yml`：固定 Node 24.13.0 / npm 11.4.2，满足 Linux 间接依赖 engines；干净安装、根 check 和完整 H5 smoke，不使用真实 provider 凭据，工作流新增不等于 CI 已绿。

## 有意不作为阻塞项的差异

| 差异 | 处理决定 | 原因 |
|---|---|---|
| Web 自定义“生成色板”筛选与色板配置文件 | 后续按真实制作需求决定，不阻塞 | 当前五套完整供应商色板可生成，编辑时可加入任意供应商色号；自定义筛选属于生成偏好 |
| Web 放大镜 | 不阻塞微信主交付 | uni-app 可在可滚动 Canvas 上编辑，数据层能力完整；移动端另做放大镜会增加遮挡和触摸冲突 |
| Native 矩形选区 / 清空 / 删除 | 不阻塞 | uni-app 已有区域填充、整色替换、单格橡皮和统一历史；矩形批处理不是主链路成功条件 |
| Native 全屏预览 | 不阻塞 | 当前 Canvas 支持横向滚动，导出不依赖预览尺寸；全屏属于移动端体验增强 |
| Web AI 图片优化 | 不阻塞本地制图迁移 | 依赖外部付费 API 与凭据，且短期主链路允许用户先在外部准备原图；不得把凭据重新引入仓库 |
| 内置裁剪 | 明确取消 | 产品决定使用系统相册裁剪，避免重复维护跨平台裁剪器 |
| 过程组合长图 | 延后 | Project 尚未保存原图资产，也没有成品照片采集入口；现在实现只能得到当前会话可用的残缺结果 |

## 微信平台真机清单

1. 微信开发者工具能读取根 `project.config.json`，编译并打开 `pages/index/index`。
2. 从相册和相机各选择一张 JPG/PNG，尺寸、方向、RGBA 解码和生成结果正常。
3. 轮廓/细腻模式各生成一次；MARD 与一个非 MARD 品牌各生成一次。
4. 画笔、连续画笔、吸管、完整色板补色、橡皮、填充、替换、去背景、撤销和重做触点无偏移。
5. 完全退出小程序并终止微信进程，再打开后当前已保存图纸、名称、制作进度、最近制作摘要和发布复盘可恢复；不能用 reLaunch 替代。最近制作不是多作品完整网格恢复库。
6. 从微信会话导入 `.pinbean.json`，再通过 `shareFileMessage` 分享项目文件。
7. 首次拒绝与允许相册权限时均有可理解反馈；允许后实际保存纯图纸、色卡图纸、备料清单、分板合集和 3:4 封面。
8. 50×50 和 80×80 各验证一次，观察 Canvas 空白、内存峰值、页面滚动和导出耗时。
9. 至少在一台 Android 和一台 iOS 真机复核相册图片清晰度和触摸位置；缺少设备时明确标为未执行 gate。

每条记录至少包含提交或工作树标识、设备型号、系统/微信/基础库版本、输入标识、模式/尺寸/供应商品牌、操作步骤、实际输出文件与结果。Android 黑块必须使用原输入、原配置和实际相册 PNG 复验；历史 H5 50/50 结果不能关闭该问题。未取得上述设备与原始文件证据的项目继续标为未验收，不宣称发布闭环完成。

## 回退方式

旧原生实现已完整保存在 `v1` 分支，但不再作为根入口回退目标。若微信平台出现阻塞，应优先在 `apps/miniapp-uni` 的 Adapter 或 Core 边界修复；确需对照旧行为时使用 `git show v1:<path>` 或独立 worktree，不把对象 Cell 模型迁回 Core，也不恢复旧原生包到 `main` workspace。

原历史、`reference/*` refs、标签和外部备份继续保留；不执行生产发布或凭据变更。
